# Global PIQA Parallel

<b>Global PIQA</b> is a participatory commonsense reasoning benchmark for over 100 languages, constructed by hand by over 350 researchers from over 65 countries around the world.
The <b>parallel</b> split is a multi-parallel dataset for 131 language varieties, covering five continents, 16 language families, and 23 writing systems.
In this parallel split, each example was machine-translated from English, then manually corrected by a native speaker of the target language.
Details are in our preprint: [Global PIQA: Evaluating Commonsense Reasoning Across 100+ Languages and Cultures (2026)](https://arxiv.org/abs/2510.24081).

<picture>
<img src="global_piqa_map.png" alt="Map of languages in Global PIQA." width="90%" />
</picture>

Each example consists of a prompt (in this case, a question) and four candidate solutions, one correct and three incorrect.
Examples were written to require knowledge of object properties or affordances, object interactions, spatial or temporal reasoning, or basic counting.
For culturally-specific examples written in each language directly, see our non-parallel split at: https://huggingface.co/datasets/mrlbenchmarks/global-piqa-nonparallel.

## License

Global PIQA is released under a [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/deed.en) license. However, we do <b>not</b> allow training of AI systems on Global PIQA, or on synthetic data that uses Global PIQA as a seed.
Global PIQA is intended for LLM evaluation only.

## Loading the dataset

Global PIQA can be loaded with the following code:
```
from datasets import load_dataset

# As a Hugging Face dataset, for the English subset:
global_piqa_eng = load_dataset('mrlbenchmarks/global-piqa-parallel', 'eng_latn')['test']
for r in global_piqa_eng:
    print(r)
    break

# To convert to a Pandas DataFrame:
global_piqa_eng.set_format('pandas')
global_piqa_eng = global_piqa_eng[:]
```

## Using Global PIQA for evaluation

As shown below, Global PIQA can be used to evaluate LLMs in either a cloze or generation format.
* The <b>cloze</b> format (for pretrained-only, or "base" models) evaluates the probability assigned by the LLM to each solution given the prompt, normalized by the solution length in bytes. The LLM is marked correct if it assigns a higher normalized probability to the correct solution than to the incorrect solutions.
* The <b>generation</b> format (for instruction-tuned models, e.g. most proprietary models) prompts the LLM with a multiple choice template including the prompt and all solutions, asking it to select option A, B, C, or D (corresponding to each solution).

<picture>
<img src="global_piqa_eval_formats.png" alt="Evaluating an LLM on a Global PIQA example, using either the cloze or generation evaluation format." width="90%" />
</picture>

Each evaluation format is implemented in the [LM Evaluation Harness](https://github.com/EleutherAI/lm-evaluation-harness):
```
# Install the harness, as in https://github.com/EleutherAI/lm-evaluation-harness
git clone --depth 1 https://github.com/EleutherAI/lm-evaluation-harness
cd lm-evaluation-harness
pip install -e .

# Cloze evaluation format:
lm_eval --model hf \
--model_args pretrained=[model_path] \
--tasks global_piqa_parallel_cloze_[lang] \
--device cuda:0 \
--batch_size 8

# Generation evaluation format:
lm_eval --model hf \
--model_args pretrained=[model_path] \
--tasks global_piqa_parallel_generation_[lang] \
--device cuda:0 \
--batch_size 8
```

## Dataset construction details

Method details are in our preprint: [Global PIQA: Evaluating Commonsense Reasoning Across 100+ Languages and Cultures (2026)](https://arxiv.org/abs/2510.24081).
The parallel split of Global PIQA was constructed as a followup to the shared task for the Multilingual Representation Learning (MRL) workshop at EMNLP 2025.
Examples were originally written in English by two native English speakers, designed to be as "culturally agnostic" as possible, to facilitate translation to a large number of languages.

Examples were then machine-translated with human corrections to all 131 language varieties in the parallel split.
All dataset contributors (including for translation corrections) were offered authorship on the Global PIQA benchmark paper.
This participatory approach is less exploitative than other approaches (e.g. compared to hiring external annotators), it is likely to result in higher quality datasets (it is constructed by NLP researchers themselves), and it gives ownership to the language communities themselves to choose how their datasets are constructed.

## Limitations

* The sample size per language is only around 100 examples; in the future, we hope that our participatory approach to benchmark construction will facilitate the construction of larger datasets.
* The parallel split of Global PIQA is translated from English, as a multi-parallel dataset across many languages. Benchmarks translated from English have been found to propagate Anglocentric perspectives and values.
Examples in the parallel split are written to be as "culturally agnostic" as possible. For culturally-specific examples, see our non-parallel split: https://huggingface.co/datasets/mrlbenchmarks/global-piqa-nonparallel.
* The parallel split of Global PIQA was machine-translated with human correction. Translations may be biased towards the original translation models used (Gemini 3.0 Flash and Gemini 2.5 Pro).
However, questions and answer candidates were translated separately to avoid introducing any subtle cues towards the correct answer.
Furthermore, in many cases, translations were heavily corrected during the manual correction stage.
* We emphasize that more languages is not necessarily better when constructing multilingual benchmarks; researchers should work with communities themselves to determine if and how they want their language(s) included.
In Global PIQA, we have sought to work together with native speakers as authors, giving authors flexibility and ownership over how their data is included.
* Large closed systems (e.g. proprietary LLMs) perform quite well on Global PIQA when averaging across languages; however, Global PIQA distinguishes between the performance of closed systems and open models, between different open models, and even between different closed systems.
It also measures variation in performance across languages within each of these models.
