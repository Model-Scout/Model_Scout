# 🇰🇷 자율주행법령 CoT 파인튜닝 데이터셋 v5

## 왜 이 데이터셋을 새로 만들었는가?

기존 [`dataset-v3`](https://huggingface.co/datasets/bluejude10/smoothie-qwen3-8b-kr-self-driving-legal-dataset-v3) 는 단순 질문-답변(Direct To Response, DTRO Style) 포맷으로 구성되어 있었습니다.

```json
// v3 포맷 (기존)
{
  "instruction": "자율주행자동차란 무엇인가요?",
  "output": "자율주행자동차란 ..."
}
```

이 방식으로 파인튜닝한 모델(`v3`)을 RAG 파이프라인과 결합하여 평가한 결과, **정답률 43%** 로 순정 모델(90%)에 크게 뒤처지는 것이 확인되었습니다. 실패의 핵심 원인은 다음과 같습니다:

| 실패 원인 | 설명 |
|-----------|------|
| **템플릿 과적합** | 모델이 논리가 아닌 답변 패턴(`아닙니다 + 설명`)을 암기 |
| **RAG 컨텍스트 무시** | 학습된 내부 패턴이 외부 검색 문서를 압도 |
| **`<think>` 태그 미사용** | Qwen3의 추론(Chain-of-Thought) 능력이 전혀 활성화되지 않음 |

---

## v5 CoT 방식의 핵심 개선

본 데이터셋은 `output` 필드 내에 **`<think>...</think>` 블록을 직접 삽입**하여, 모델이 최종 답변 이전에 반드시 4단계 추론 과정을 밟도록 학습합니다.

```json
// v5 포맷 (본 데이터셋)
{
  "instruction": "자율주행자동차 임시운행허가를 받으려면 어떤 서류가 필요한가요?",
  "output": "<think>\n1. 질문 파악: 임시운행허가 신청 시 필요한 서류를 묻고 있다.\n2. 법령 검토: 자율주행자동차법 시행규칙에서 허가 신청 서류를 확인한다.\n3. 서류 확인: 운행계획서, 안전운행요건 설명서, 보험 가입 증명서 등이 필요하다.\n4. 결론 도출: 세 가지 주요 서류가 필요하다.\n</think>\n자율주행자동차 운행계획서, 안전운행요건에 관한 설명서, 보험 가입 증명서 등이 필요합니다."
}
```

### CoT 4단계 추론 구조

모든 데이터는 아래의 고정된 추론 알고리즘을 따릅니다:

```
1. 질문 파악   → 무엇을 묻는지 명확히 정의
2. 법령 검토   → 적용 법률·조항 특정
3. 조건 확인   → 세부 요건·예외 조항 식별
4. 결론 도출   → 논리적 최종 답변 생성
```

## 데이터셋 구성

| 항목 | 내용 |
|------|------|
| **규모** | 750개 QnA 쌍 |
| **도메인** | 대한민국 자율주행자동차 관련 법령 |
| **포맷** | JSON (`instruction` / `output`) |
| **CoT 포함** | ✅ (`<think>...</think>` 블록 내 4단계 추론) |
| **언어** | 한국어 |
| **베이스 법령** | 자동차관리법, 자율주행자동차법 시행규칙, 여객자동차법 등 |

### 포함 질문 유형

- 법령 정의 및 개념 확인형
- 오답 유도형 함정 질문 (법령 조건 역전, 유사 개념 혼용)
- 절차·서류·기한 확인형
- 책임 주체 및 예외 규정 판단형

## 6개 모델 종합 벤치마크 결과

동일 RAG 파이프라인(BGE-M3 + Qdrant, 자율주행 법령 txt + QnA JSON 임베딩)에서 15개 오답 유도 질문으로 평가한 최종 결과입니다.

| 순위 | 모델 | 정답률 | 비고 |
|:---:|------|:------:|------|
| 1 | Non-FT Qwen3-14B | **90%** | 순정 |
| 1 | Non-FT Qwen3-8B | **90%** | 순정, 최고 효율 |
| 3 | Gemma3n E4B | **87%** | ~4B 파라미터로 14B 대비 3%p 차이 |
| 4 | DTRO 8B (타 도메인 FT) | 80% | 전력설비 지식 도메인으로 파인튜닝된 모델 |
| 5 | **FT-8B Q8/CoT (본 데이터셋)** | **60%** | v5 CoT 파인튜닝, +17%p 개선 |
| 6 | FT-8B Q4 (v3 데이터셋) | 43% | DTRO 단순 QnA 파인튜닝 |

### v3 vs v5 데이터셋 포맷 비교

| 구분 | v3 (Direct To Response) | **v5 (본 데이터셋, CoT)** |
|------|------------------------|--------------------------|
| 포맷 | 단순 `instruction` → `output` | `<think>` 추론 블록 포함 |
| `<think>` 활성화 | ❌ | ✅ |
| 추론 구조 | 없음 | 4단계 고정 알고리즘 |
| 파인튜닝 결과(정답률) | 43% | 60% (+17%p 개선) |
| 한계 | 과적합, RAG 무시 | 소규모 데이터셋 일반화 한계 |

### 핵심 인사이트

- **RAG 환경에서는 모델 크기보다 RAG 품질이 중요**: 4B급 Gemma3n E4B가 14B 대비 3%p 차이에 불과
- **파인튜닝이 유일하게 우위인 영역**: Q8(자동차손해배상 운행자 책임 원칙) — RAG만으로 해결 불가능한 법적 해석 패턴에서 순정 모델 3개 전부 실패, FT 모델만 성공
- **현 시점 권장 아키텍처**: 순정 Non-FT 8B + QnA RAG 직접 임베딩 (90%, ~6GB VRAM)

> 자세한 실험 분석은 [모델 리포지토리 README](https://huggingface.co/bluejude10/Smoothie-Qwen3-8B-KR-Self-Driving-Legal-v3)를 참조하십시오.  
> 본 데이터셋으로 구동되는 **RAG 챗봇 전체 코드** (Qdrant DB 사전 구축 포함, 즉시 실행 가능): [Legal_RAG_Chatbot_Qdrant_BGE](https://github.com/aremany/Legal_RAG_Chatbot_Qdrant_BGE)
