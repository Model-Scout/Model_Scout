# K-BrowseComp

**K-BrowseComp** is a Korean version of [BrowseComp](https://arxiv.org/abs/2504.12516): a web-browsing agent benchmark. Items are grounded in Korean contexts and require retrieving information across multiple Korean websites.

The 300-question verified subset is **entirely handcrafted by native Korean speakers** and every item underwent thorough manual revision and validation.

- 📄 Paper: https://arxiv.org/abs/2606.02404
- 💻 Code: https://github.com/prometheus-eval/K-BrowseComp

## Subsets

| Config | Size | Description |
|---|---|---|
| `verified` | 300 | **Main benchmark.** Human-written and human-validated Korean browsing problems. |
| `verified_with_metadata` | 300 | Same 300 problems, plus the auxiliary annotation collected during construction (see below). |
| `synthetic` | 100 | A diagnostic stress split generated by a browsing agent using hard human-written exemplars and failure-mode-targeted prompting, then adversarially filtered. |

### `verified` fields

- `problem` — the question (Korean).
- `answer` — the gold short answer.
- `type` — `multi-hop` or `parallel`.
- `category` — topical category (e.g., 엔터테인먼트/미디어, 교육/대학/시험).

`synthetic` uses the same four fields.

### `verified_with_metadata` extra fields

These come from the structured submission each annotator filed and are provided for analysis / trajectory grading. They are descriptive of the intended solution and are not required to grade an answer.

- `expected_chain` — the reasoning trajectory the annotator expected an agent to follow, as ordered steps with supporting source URLs.
- `checklist` — the key intermediate entities/values an agent should ideally surface on the way to the answer (a soft signal, not a hard requirement).
- `korean_specific_keyword` — what makes the question grounded in Korean context.
- `rationale` — why the example was created / why it should require Korean-context browsing.
