# 규칙 기반 입력 가드

`input_guard.py`는 외부 의존성이나 LLM 호출 없이 동작하는 1차 입력 검사다.

| 대상 | 처리 |
|---|---|
| 일반적인 이메일 주소 | `[EMAIL]`로 마스킹 |
| 국내 휴대전화 번호 및 `+82` 형식 | `[PHONE]`으로 마스킹 |
| 주민등록번호 형태의 숫자 | `[RRN]`으로 마스킹. 신원·유효성 검증은 하지 않음 |
| 알려진 API 키 접두사·Bearer·JWT·명시적 키 대입(영문+숫자 16자 이상) | 요청 중단, 값 제거 및 실제 키 폐기·재발급 안내 |
| `password=값`, `비밀번호: 값` 등 | 요청 중단, 값 제거 및 실제 비밀번호 변경 안내 |
| IP 주소·사람 이름·회사명 | 기본 유지 |
| 지시 무시·역할 변경·시스템 프롬프트 추출·키 유출·형식 변경 패턴 | 의심 유형만 로그에 기록. 원문 삭제나 자동 차단은 하지 않음 |

`sk-...`, `password=...`, `<YOUR_KEY>` 등 명백한 예시 표기는 허용한다.
단어만 언급한 `API 키 없이 쓸 모델`, `비밀번호 탐지 모델`은 차단하지 않는다.
탐지 규칙은 보수적인 형식 검사이므로 실제 자격증명인지 검증하지 않으며 오탐·누락이 가능하다.

## 적용 경로

- 공개 `POST /api/chat`: 첫 질문·후속 질문·되묻기 답변·저장 결과 질문 모두 검사한다. 그룹 제목과 사용자 메시지 저장, 내부 AI 요청 전에 처리한다.
- 내부 `POST /ai/recommend`: 공개 백엔드를 우회한 직접 호출도 검사한다. `Command(resume=...)`와 질문용 LLM에는 마스킹한 입력만 전달한다.
- 저장 결과 질문의 `context`(대화 기록·README 출처)는 사용자가 고칠 수 없으므로 차단하지 않고 비밀값을 `[SECRET]`으로 마스킹한다. 과거 DB 원문을 일괄 수정하지는 않는다.
- 차단은 HTTP 400과 고정된 한국어 메시지로 응답한다. 비밀값·일치한 원문을 오류 메시지나 가드 로그에 넣지 않는다. 가드 로그에는 마스킹 종류와 인젝션 의심 종류만 남긴다.
- 두 Docker 이미지 모두 같은 `shared` 패키지를 포함한다. CLI·인프로세스 그래프 직접 호출은 HTTP 가드 경계 밖이므로 호출자가 `protect_text`를 먼저 적용해야 한다.

## 한계와 다음 단계

의심 패턴은 탐지 신호일 뿐이며, 현재 인젝션 문장은 기존 검색 흐름으로 진행한다.
인용된 공격 문구를 검색하는 정상 질의와 실제 공격을 구분하는 LLM 판단은 후속 작업이다.
외부 README·모델 카드의 명령 삽입, 출력 검증, MCP 권한 제한은 이 입력 가드의 범위에 포함되지 않는다.
기존 저장 데이터·외부 관측 시스템·프록시가 이미 수집한 원문은 소급 삭제하지 않는다.

정규식만으로 완전한 인젝션 방어를 보장하지 않으며, 단계별 방어가 필요하다.
참고: [OWASP LLM Prompt Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html).
