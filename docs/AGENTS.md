# 기획서 수정 가이드

`docs/index.html`은 Model Scout 확장 기획서입니다. GitHub Pages로 배포되며, main 브랜치에 push하면 1~2분 뒤 링크에 반영됩니다.

이 문서는 사람과 AI 도구(Claude Code, ChatGPT/Codex 등)가 모두 읽는 수정 규칙입니다.

## 수정 방법

1. `git pull`로 최신 버전을 받습니다.
2. `docs/index.html`을 직접 고치거나, AI 도구에 "docs/AGENTS.md 규칙대로 기획서의 ○○ 섹션을 고쳐줘"라고 요청합니다.
3. 브라우저로 `docs/index.html`을 열어 확인합니다.
4. 맨 아래 **변경 이력** 표에 한 줄 추가합니다.
5. commit 후 push합니다. 여러 명이 동시에 고칠 때는 브랜치를 만들어 PR로 올립니다.

## 규칙

- **한 파일 유지**: CSS는 `<head>`의 `<style>` 안에 둡니다. 별도 파일이나 빌드 도구를 추가하지 않습니다.
- **섹션 구조**: 각 섹션은 `<!-- ============ N. 이름 ============ -->` 주석으로 시작하는 `<section id="...">`입니다. 섹션을 추가·삭제하면 왼쪽 목차(`nav.toc`)도 함께 고칩니다.
- **색**: `:root`의 CSS 변수만 사용합니다. 색 값을 직접 쓰지 않습니다. 다크 모드 변수도 같이 맞춥니다.
- **상태 칩**: 섹션 제목 옆에 상태를 표시합니다.
  - `<span class="chip done">구현됨</span>`: 이미 코드에 있는 것
  - `<span class="chip prop">제안</span>`: 제안했지만 아직 합의 전
  - `<span class="chip open">논의 필요</span>` / `조사 필요`: 결정이나 확인이 필요한 것
  - 팀에서 합의하면 `prop` → `done` 또는 "확정"으로 바꿉니다.
- **사용 가능한 블록**: `.card`, `.callout`(`.callout.warn`), `.stats` > `.stat`, `.table-wrap` > `table`, `.two`(2단), `.flow` > `.node`(`.node.new`) — 새 스타일보다 이것들을 먼저 씁니다.
- **사실 확인**: 수치는 루트 `README.md`나 `test/` 리포트에서 가져오고, 기준 날짜를 함께 적습니다. 확인하지 않은 외부 정보(데이터셋 이름, API 조건 등)는 "조사 필요"로 표시하고 추측해서 쓰지 않습니다.
- **모바일**: 860px 이하에서는 한 단으로 바뀝니다. 표는 `.table-wrap`으로 감싸서 가로 스크롤되게 합니다.
- **변경 이력**: 표의 맨 위에 `날짜 | 작성자 | 내용` 한 줄을 추가합니다.
