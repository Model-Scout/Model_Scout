Model Scout · 확장 기획서

아이디어를 적으면, 필요한 데이터와 모델을 함께 찾아준다

지금의 Model Scout는 요구사항에 맞는 Hugging Face 모델을 근거와 함께 추천합니다. 이번 확장에서는 같은 방식으로 필요한 공공데이터·학습 데이터까지 찾아, 기획 단계에서 바로 착수할 수 있게 만듭니다.

상태: 초안 · 논의 중 최종 수정: 2026-10-02 작성: Model Scout 팀

한눈에 보기

  • 무엇을: 사용자가 만들고 싶은 AI 서비스를 자연어로 적으면, 필요한 데이터셋과 모델을 각각의 출처·라이선스·근거와 함께 추천합니다.
  • 왜: 아이디어 단계에서 가장 먼저 막히는 곳은 "어떤 모델을 쓸까"보다 "데이터를 어디서 구할까"인 경우가 많습니다.
  • 어떻게: 기존 모델 추천 파이프라인(수집 → metadata → semantic evidence → 임베딩 → hybrid 검색)을 데이터셋 카탈로그에도 적용하고, 앞단에 아이디어 분해 단계를 추가합니다.
  • 원칙: 근거 없는 추천은 하지 않습니다. AI 모델이 필요 없는 아이디어라면 그렇다고 답합니다.

문제 정의

AI 서비스를 기획하는 사람(부트캠프 수강생, 사이드 프로젝트 개발자, 초기 스타트업)은 아이디어를 실제 작업으로 옮길 때 다음 질문에 막힙니다.

  1. 데이터: 이 서비스에 필요한 데이터가 공개돼 있나? 어디서, 어떤 조건으로 받을 수 있나?
  2. 모델: 한국어를 지원하고, 우리 환경(GPU, 라이선스)에서 쓸 수 있는 모델은 무엇인가?
  3. 필요성: 애초에 이 문제에 AI 모델이 필요한가, 아니면 데이터와 일반 API로 충분한가?

지금은 공공데이터포털, AI Hub, Hugging Face를 따로 검색하고 결과를 직접 맞춰봐야 합니다. 각 사이트의 검색은 키워드 위주라서 "주차 공간을 찾는 앱" 같은 목적 중심 질의에 약합니다.

현재 Model Scout 구현됨

자연어 요구사항을 받아 Hugging Face 모델을 찾고, 조건을 통과한 후보와 모델 카드 근거를 함께 제공합니다. (수치는 2026-09-28 snapshot 기준)

3,606추천 corpus 모델 수
(Core 1,478 · Low Popularity 2,128)
9대상 task
(텍스트 생성, 임베딩, 분류, 요약, 번역, ASR 등)
1,536임베딩 차원
(text-embedding-3-small)
48 + 28constraint 골든셋 질의 +
사례 기반 semantic 골든셋 질의
  • 한국어 지원 근거, 라이선스, 파라미터 수, context length, 양자화, 실행 환경을 metadata로 정리합니다.
  • README를 claim 단위로 나누고, 각 claim에 원문 인용(supporting_quote)을 연결합니다.
  • Supabase pgvector에 저장하고, dense·sparse·hybrid 검색에 hard filter를 적용합니다.
  • TTL 기반 증분 동기화로 변경된 모델만 다시 처리합니다.

이번 확장의 기반이 되는 것은 "근거와 함께 추천한다"는 원칙과 재사용 가능한 수집·검색 파이프라인입니다.

확장 제안 제안

입력을 "모델 요구사항"에서 "서비스 아이디어"로 넓히고, 출력에 데이터셋 추천과 AI 필요도 판단을 더합니다.

지금

입력: "한국어 요약 모델, 8B 이하, 상업 이용 가능"

출력: 조건을 만족하는 모델 + 모델 카드 근거

확장 후

입력: "주차장 위치를 찾아주는 AI 앱을 만들고 싶다"

출력: 필요한 데이터셋 + 필요한 경우 모델 + 각각의 근거·이용 조건 + AI 필요도 판단

핵심 신규 기능

  1. 아이디어 분해: LLM이 아이디어를 "필요한 데이터"와 "AI가 맡을 기능"으로 나누고, 각각을 검색 질의로 바꿉니다.
  2. 데이터셋 카탈로그 검색: 공개 데이터셋의 메타데이터를 수집·임베딩해서 목적 중심으로 검색합니다.
  3. 통합 답변: 데이터와 모델 추천을 하나의 착수 가이드로 묶습니다. AI가 필요 없는 부분은 명시합니다.

사용 시나리오

아래는 기대하는 응답의 형태입니다. 실제 데이터셋 이름과 내용은 구현할 때 카탈로그에서 확인해야 합니다.

💬 "주차장 위치를 찾아주는 AI 앱을 개발하고 싶어"

① 아이디어 분해

  • 필요한 데이터: 주차장 위치(좌표), 요금, 운영 시간, 주차면 수, (가능하면) 실시간 잔여 면수
  • AI가 맡을 기능: "강남역 근처 저렴한 주차장" 같은 자연어 질의를 검색 조건으로 바꾸기
  • AI 없이 되는 기능: 위치 기반 검색, 지도 표시, 거리순 정렬

② 추천 데이터

  • 공공데이터포털의 전국 주차장 정보 표준데이터 (위치·요금·운영 시간) — 이용 조건 표시
  • 지자체별 실시간 주차 정보 오픈API (제공 지역 한정) — 제공 범위 표시

③ 추천 모델

  • 질의 해석용 한국어 소형 LLM 후보 (Model Scout 기존 검색 결과 + 근거)

④ 판단

  • 이 서비스의 핵심은 데이터와 지도 API이고, AI 모델은 검색 편의 기능입니다. 모델 없이도 MVP를 만들 수 있습니다.

MVP 범위 제안

포함

  • 아이디어 분해 단계
  • 공공데이터포털 카탈로그 수집·검색
  • 데이터셋별 출처 링크, 제공 기관, 형식, 이용 조건 표시
  • 기존 모델 검색과 결과 통합
  • AI 필요도 판단 문구

제외 (이후 검토)

  • 실제 데이터 다운로드·가공
  • 오픈API 실시간 호출
  • AI Hub, HF Datasets 연동
  • 코드 생성, 아키텍처 자동 설계
  • 라이선스의 법적 판단 (정보 제공만)

MVP는 "어떤 데이터가, 어디에, 어떤 조건으로 있는지"를 추천하는 데서 멈춥니다. 데이터를 직접 가져오는 기능은 범위가 크게 늘어나므로 별도 단계로 다룹니다.

평가 계획 제안

모델 검색에 쓰는 골든셋 방식을 데이터셋 검색에도 똑같이 적용합니다.

  • 아이디어 골든셋: 서비스 아이디어 30개 내외. 각 아이디어에 정답 데이터셋 ID, 정답 모델 ID, AI 필요도 라벨을 붙입니다.
  • 검색 지표: Recall@5, MRR, nDCG@5, Hit@5 (기존 지표와 동일)
  • 분해 품질: 필요한 데이터 항목을 빠뜨리지 않았는지 사람이 판정합니다.
  • 근거 품질: 추천 데이터마다 출처 링크와 이용 조건이 있는지, 인용이 원문과 일치하는지 확인합니다.
  • 판정 방식: 지금 하고 있는 human judging batch 방식(후보 pool → 팀원 판정)을 재사용합니다.

리스크와 대응

리스크영향대응
AI가 필요 없는 아이디어에 모델을 억지로 추천신뢰도 하락AI 필요도 판단을 출력에 넣고, 골든셋에 "모델 불필요" 사례를 포함
평가 작업이 두 배로 늘어남일정 지연모델 골든셋 평가를 먼저 끝내고 확장 착수. 데이터 골든셋은 작게 시작
데이터 이용 조건 누락·오표기사용자 피해이용 조건 필드가 없으면 "확인 필요"로 표시. 추측해서 채우지 않음
카탈로그 수집 실패·포맷 변경검색 불가기존과 같은 fail-closed 정책: 실패하면 이전 snapshot 유지
범위가 데이터 가공·API 호출로 커짐제품 정체성 흐려짐MVP 제외 목록을 명시하고 변경은 이 문서에서 합의

결정할 것 논의 필요

  1. 확장을 할지, 한다면 모델 평가를 끝낸 뒤에 시작할지
  2. MVP 데이터 소스를 공공데이터포털 하나로 시작할지
  3. 사용자에게 보여주는 형태: 웹 UI / MCP 도구 / LangChain 에이전트 중 무엇을 우선할지
  4. 상업 라이선스를 hard 조건으로 둘지 (모델 검색에서도 아직 미정)
  5. 단계별 담당자
