## 결론과 다음

- **운영 반영 판단:**

### 통합안에 반영할 점

- **지역은 시도와 시군구를 따로 받습니다.** 예: `region: "충북"`, `region_detail: "청주"`. 충북으로 묶어 후보를 찾고(필터·검사는 시도), 청주 요구로 결과를 구별합니다. 충북 전체 자료는 청주를 포함할 수 있어 후보로 남고, 충북 제천만의 자료는 청주 요청의 정답이 아닙니다. 시군구 하나만 받으면 지역 범위 확인이 빠집니다(h003).
- **신선도는 셋으로 나눕니다.** 요청한 갱신 간격, 현재 상태가 필요한지, 실제 데이터의 갱신·반영 지연이 확인됐는지입니다. 앞의 둘은 질문에서, 마지막은 데이터 카드·공식 근거에서 옵니다. 실시간은 지금처럼 하드 필터로 쓰지 않습니다.
- **필수 조건과 '우선·따로 구분' 요청을 나눕니다.** 예: h011 "1유형이 아닌 자료는 따로 구분", h020 "접근성 정보 우선".
- **같은 호출에서 출력 칸을 늘리면 `dataset_query`·`dataset_terms`도 달라질 수 있습니다.** 기존 검색 문장 지침은 그대로 두고 조건 칸을 붙인 뒤, 검색 결과가 나빠지지 않는지 개발 58문항과 이 32문항으로 다시 확인합니다.
