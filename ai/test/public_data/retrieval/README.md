## 2. 질문 유형과 조건 명세

### 분류 기준 (계획 문서의 두 축을 그대로 적용)

- **대상 지정:** 데이터 대상과 필요한 항목이 질문에 이름으로 나오거나, 대상의 기본 기록(위치·목록·기본 정보)이면 "지정"입니다. 목적 문구(앱, 알림, 챗봇)를 지워도 필요한 데이터가 같으면 "지정"입니다.
- **추론:** 필요한 항목을 목적에서 도출해야 하면 "추론"입니다. 예: '가장 싼' → 가격, '입양 연결' → 보호 중 동물 공고, '서리 위험' → 최저기온 예보, '문 연' → 운영 시간.
- **제공 조건:** 지역, 제공 방식(API·파일), 실시간, 상업 이용 중 하나라도 **사용자가 명시**하면 "조건 있음"입니다. 목적에서 추론한 요구(예: 알림 앱 → 자주 갱신)는 `inferred_needs`에만 적고 조건으로 바꾸지 않습니다.
- **multi_dataset:** 서로 다른 종류의 데이터가 2개 이상 필요하면 조건 유무와 관계없이 multi_dataset입니다. 같은 데이터의 여러 항목은 1종입니다.

### BM25 토큰화 (`tokens()`)

- **단어:** 한글·영문·숫자가 이어진 덩어리이며 소문자로 바꿉니다. 그 밖의 문자(공백, 문장부호, `_`, `/`)에서 끊습니다.
  - 숫자는 숫자 덩어리 그대로 둡니다.
  - 숫자와 한글이 붙은 말은 한 단어로 둡니다(예: `1유형`).
  - 데이터 ID `data_go_kr/15000115`는 `data`, `go`, `kr`, `15000115`로 나뉩니다. `data`·`go`·`kr`는 모든 카드에 있어 거의 점수가 없습니다.
- **2-gram:** 한글만 2자 이상 이어진 덩어리에서 만들고 `#`을 붙입니다. 예: `공영주차장` → `#공영` `#영주` `#주차` `#차장`. 조사가 붙은 질문(`주차장을`)도 맞출 수 있습니다.
- **구현:** 형태소 분석기 없이 numpy만 씁니다. 형태소 분석기 비교는 별도 실험으로 남깁니다.

### 채널별 문서 범위와 청크 수의 영향

- **문서 범위가 채널마다 다릅니다.** Dense는 전체 청크를 쓰고, BM25는 카드만 씁니다.

- 공공 데이터셋 15,152개 중 13,691개는 카드 청크 하나뿐입니다(전체 17,312청크).

### 임베딩

## 14. 후보별 조건 판정과 표시 (2026-11-21, 브랜치 `feat/decompose-conditions`)

- **서비스 판정 모듈 `ai/condition_checks.py`:**
  - 서비스 데이터 후보마다 조건을 충족 / 불충족 / 미확인으로 판정하고, 근거(`basis`)와 확인 범위(`scope`)를 남깁니다.
  - 부분 대안(전국 요청에 서울 자료 등)은 `partial_alternative`로 따로 표시합니다. 조건은 불충족으로 둡니다.
  - 검색 순위와 후보 구성은 바꾸지 않습니다.
  - 서버의 그래프와 v2 카드만 읽습니다. 골든셋이나 평가 파일에 의존하지 않습니다.
- **확정하지 않는 사실:**
  - API 주소 등록은 호출 성공이 아닙니다.
  - 포털 '실시간' 표기는 현재 값을 보장하지 않습니다.
  - 현재 값·갱신 간격은 제공 방식이 아니라 "어느 시점의 값이며 얼마나 자주 바뀌는가"로 판정합니다.
    - 파일도 주기적으로 다시 만들어질 수 있고, API도 오래된 통계만 줄 수 있습니다.
    - 포털 갱신 표기('실시간', '매일', '연간', '1회성')는 값·파일 게시·안내 정보 중 무엇의 주기인지 확인되지 않습니다. 그래서 판정에는 쓰지 않고, 미확인 판정의 근거·주의사항으로만 보여 줍니다.
    - 파일, 파일 자동변환 OpenAPI("업로드된 파일을 API로 제공하는 방식이라 최신성은 원본 파일 갱신에 의존"), 일반 API 모두 그것만으로는 **미확인**입니다.
    - 공식 설명 중 기준일·지연을 말하는 문장(`facts.limits`)은 원문 그대로 근거에 붙입니다.
    - **불충족**은 공식 설명이나 명세에서 값의 기준 시점·갱신 간격이 확인되고, 그것이 사용자 요구와 충돌할 때만입니다(예: "2023년 말 기준, 이후 갱신 안 함"인데 현재 값 요구).
    - 지금 카드에는 이를 구조화한 필드가 없어서 현재 값·갱신 간격은 모두 미확인입니다. 일괄 기준(예: "매일보다 느리면 불충족")은 두지 않습니다. 목적에 따라 필요한 최신성이 다르기 때문입니다.
    - 한때 느린 표기나 1회성 표기를 불충족으로 본 적이 있으나 되돌렸습니다. 해당 67쌍은 골든셋에서 모두 0점이었지만, 이는 규칙이 맞다는 증명이 아니었습니다.
  - 우리 검색 목록의 자동 갱신(GitHub Actions)은 켜지 않습니다. 이것은 원 제공처 데이터의 갱신과는 별개입니다. 판정의 확인 범위에 "추천 근거는 고정 수집본 기준, 제공처의 현재 상태는 재확인하지 않음"을 밝힙니다.
  - API만 표기돼 있다고 파일이 없는 것이 아닙니다. 파일만 표기돼 있다고 API가 없는 것도 아닙니다.
    - 실험용 판정기는 파일만 표기된 경우를 'API 불충족'으로 봤습니다. 서비스는 미확인으로 봅니다.
