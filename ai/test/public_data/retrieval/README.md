## 2. 질문 유형과 조건 명세

### 분류 기준 (계획 문서의 두 축을 그대로 적용)

- **대상 지정:** 데이터 대상과 필요한 항목이 질문에 이름으로 나오거나, 대상의 기본 기록(위치·목록·기본 정보)이면 "지정"입니다. 목적 문구(앱, 알림, 챗봇)를 지워도 필요한 데이터가 같으면 "지정"입니다.
- **추론:** 필요한 항목을 목적에서 도출해야 하면 "추론"입니다. 예: '가장 싼' → 가격, '입양 연결' → 보호 중 동물 공고, '서리 위험' → 최저기온 예보, '문 연' → 운영 시간.
- **제공 조건:** 지역, 제공 방식(API·파일), 실시간, 상업 이용 중 하나라도 **사용자가 명시**하면 "조건 있음"입니다. 목적에서 추론한 요구(예: 알림 앱 → 자주 갱신)는 `inferred_needs`에만 적고 조건으로 바꾸지 않습니다.
- **multi_dataset:** 서로 다른 종류의 데이터가 2개 이상 필요하면 조건 유무와 관계없이 multi_dataset입니다. 같은 데이터의 여러 항목은 1종입니다.

## 4. 검색 설정 (`pilot.SETTINGS`)

| 경로 | 입력 | 방식 |
|---|---|---|
| `hg_question` | 질문 원문의 벡터 | 기존 `rank_datasets`(개념·키워드 없이). 하한선, 가점, `commercial_only`는 기존 그대로 |
| `hg_terms` | 질문 벡터 + 라벨 `dataset_terms`와 지역 | 2026-11-16 기준선과 같은 방식. **검색어 보조 참고 경로이며 주 실험 입력이 아님** |
| `dense` | 질문 원문의 벡터 | 데이터셋의 모든 청크와 코사인 유사도를 구하고, 데이터셋 점수는 가장 높은 청크 점수 |
| `bm25` | 질문 원문 | 카드 청크만으로 Okapi BM25(k1 1.2, b 0.75). 질의어는 중복 제거 |
| `hybrid` | 질문 원문과 벡터 | dense·bm25가 각자 상위 100개를 확보한 뒤 Weighted RRF(k 60, 가중치 0.5/0.5). 의미 유사도 하한선으로 BM25 후보를 먼저 빼지 않음 |

### BM25 토큰화 (`tokens()`)

- **단어:** 한글·영문·숫자가 이어진 덩어리이며 소문자로 바꿉니다. 그 밖의 문자(공백, 문장부호, `_`, `/`)에서 끊습니다.
  - 숫자는 숫자 덩어리 그대로 둡니다.
  - 숫자와 한글이 붙은 말은 한 단어로 둡니다(예: `1유형`).
  - 데이터 ID `data_go_kr/15000115`는 `data`, `go`, `kr`, `15000115`로 나뉩니다. `data`·`go`·`kr`는 모든 카드에 있어 거의 점수가 없습니다.
- **2-gram:** 한글만 2자 이상 이어진 덩어리에서 만들고 `#`을 붙입니다. 예: `공영주차장` → `#공영` `#영주` `#주차` `#차장`. 조사가 붙은 질문(`주차장을`)도 맞출 수 있습니다.
- **구현:** 형태소 분석기 없이 numpy만 씁니다. 형태소 분석기 비교는 별도 실험으로 남깁니다.

### 채널별 문서 범위와 청크 수의 영향

- **문서 범위가 채널마다 다릅니다.** Dense는 전체 청크를 쓰고, BM25는 카드만 씁니다.
- **청크 수의 영향은 완전히 없어지지 않았습니다.** 데이터셋별 최댓값은 중복 합산을 막습니다. 하지만 청크가 많은 데이터셋은 높은 점수를 얻을 기회가 더 많습니다.
- 공공 데이터셋 15,152개 중 13,691개는 카드 청크 하나뿐입니다(전체 17,312청크).

### 임베딩

- 현재 고정본의 text-embedding-3-small 벡터를 재사용합니다. BGE-M3 등은 별도 실험입니다.

## 5. 평가 정책

- **같은 데이터 중복 처리:** v2 그래프가 같은 데이터로 확인한 사본은 한 데이터셋으로 합치고, 첫 순위만 남깁니다. 파일럿 1의 상위 결과에서 합쳐진 사본은 0건이었습니다.
- **판정 상태:** v6 라벨을 그대로 읽습니다.
  - 1·2점은 관련, 0점과 제외 대상은 판정됨입니다.
  - 보류(라벨의 `unjudged`)와 판정 기록이 없는 데이터는 적중이 아닙니다.
- **raw와 condensed:**
  - raw는 보류와 미판정을 순위에 남깁니다.
  - condensed는 보류와 미판정을 순위에서 뺍니다.
- **지표:** `retrieval_lab.metrics.ranking_metrics`(R@5/10, P@5/10, F1, Hit@10, MRR@5, nDCG@5, MAP@5)를 그대로 씁니다.
  - 대안 포함(1점 이상)과 2점 정답을 따로 계산합니다.
  - 2점 정답이 없는 추천 10문항(p003, p004, p007, p010, p011, p021, p026, p033, p047, p056)은 2점 평균에서 빼고, 그 수를 표에 적습니다.
- **주 선택 지표 후보:** 2점 정답 R@10. 대안 포함 성적을 함께 봅니다.
- **기권 5문항:** 지표에서 뺍니다. 반환 수와 상위 10의 판정 데이터·보류·미판정 수만 적습니다. abstention 정확도는 빈 결과를 돌려주는 경로가 생길 때까지 보고하지 않습니다.
- **그 밖에 기록하는 것:** 반환 수, 판정률, 보류, 완전 미판정, 걸러진 불충족, 조건별 미확인·부분, 질문별 개선·악화, 지연 시간(질문 임베딩 제외).

## 6. 미판정 후보와 Coverage

### 미판정 후보

- `runs/<run>/unjudged_blind.jsonl`은 다섯 경로 상위 10의 합집합에서 v6가 판정하지 않은 쌍입니다.
- 경로와 순위는 지우고, 질문·조건·카드 사실·자동 조건 검사만 남겼습니다. 순서는 고정 시드로 섞었습니다.
- 판정 칸(`judgment`, `grade`, `evidence`)은 비어 있습니다. 검색됐다는 이유로 점수를 주지 않습니다.
- 근거가 부족하면 보류합니다. 판정하면 v6를 덮어쓰지 않고 새 라벨 버전(v7)을 만든 뒤, 모든 경로를 같은 라벨로 다시 채점합니다.

### Coverage

- `runs/<run>/coverage_worksheet.jsonl`은 multi_dataset 7문항에서 관련 판정된 88쌍의 작업표입니다. 요구 항목은 명세의 `aspects`에서 가져옵니다.
- 충족 항목 칸(`covers`, `covers_fully`)은 비어 있어, **Coverage는 아직 계산하지 않았습니다.**
- 기존 관련성 점수는 바꾸지 않습니다. 작업표의 `grade_v6`는 읽기용입니다.
