# GS Qwen3.8 27B — 코드 분석·수정 작업용 학습 모델

**C++·C# 개발자가 코드의 오류 원인을 찾고, 필요한 도구로 파일을 수정하도록 돕기 위해 학습했습니다.**

이 모델은 Qwen3.8-27B에 **LoRA 지도학습(SFT)과 검증된 참조 사례를 이용한 교정 SFT**를 적용하고, LoRA를 BF16 가중치에 병합한 결과입니다. 강화학습으로 만든 모델은 아닙니다. 사내 문서나 RAG 데이터베이스도 모델 파일에 포함되어 있지 않습니다.

빠른 설명: [파인튜닝과 RAG — 실제 학습 과제와 사내 규칙 적용을 좌우 2열로 비교](docs/finetuning-and-rag.md)

| 현재 배포 모델 | 확인된 값 |
|---|---|
| 원본 모델 | `Qwen/Qwen3.8-27B` |
| 학습 경로 | 원본 → 1,400회 학습 체크포인트 선택 → 교정 SFT 9회 |
| 코드 수정 평가 | 자체 C++·C# 작업 **17/18건** 통과 |
| 도구 호출 평가 | BFCL v4 선정용 표본 **47/50문항** 정답 |
| GS 서빙명 | `gs-qwen27b-agent-sft1400-corrected-mtp` |
| 현재 GS 서빙 제한 | 총문맥 **131,072토큰**, 최대 출력 **65,536토큰** |

위 평가는 소규모 개발용 평가입니다. 전체 BFCL·SWE-bench 리더보드 점수나 원본보다 모든 능력이 좋아졌다는 의미는 아닙니다.

## 1. 무엇을 개선하려고 했나

목표는 코드 생성 문장을 그럴듯하게 만드는 것에서 더 나아가, **실제 개발 작업을 수행하는 능력**을 개선하는 것입니다.

- **원인 분석:** 증상과 관련 코드를 읽고, 여러 파일·함수 사이의 호출 관계에서 오류 원인을 찾기.
- **도구 사용:** 요청에 맞는 도구와 입력 인자를 선택하고, 필요하면 여러 도구를 호출하기.
- **실제 수정:** 수정 방법을 설명하는 데 그치지 않고 파일에 필요한 변경을 저장하기.
- **영향 확인:** 기존에 동작하던 기능을 유지하며, 실행한 검증 결과를 근거로 수정 내용을 설명하기.
- **불필요한 호출 억제:** 제공된 도구로 해결할 수 없는 요청에는 무관한 도구를 호출하지 않기.

이 항목들은 **학습 목표**입니다. 각 항목을 모두 달성했다고 판정한 것은 아니며, 확인된 결과는 아래 평가 표에 따로 정리했습니다.

## 2. 어떤 데이터를 선정했고, 왜 사용했나

전체 학습 릴리스에는 **9,135행**을 준비했습니다. 여기서 **한 행은 프로젝트 하나가 아니라 학습 예제 또는 작업의 한 단계**입니다.

| 데이터 출처 | 전체 준비량 | 선택된 1,400회 모델이 학습한 양 | 선정 이유와 가공 방법 |
|---|---:|---:|---|
| [CommitPackFT](https://huggingface.co/datasets/bigcode/commitpackft) | **7,118행**<br>C# 5,302 / C++ 1,816 | **4,375행**<br>C# 3,280 / C++ 1,095 | 공개 저장소의 수정 전·후 코드와 수정 설명이 있어, 요청을 실제 코드 변경으로 옮기는 학습에 사용했습니다. 코드 차이를 정확한 문자열 교체 방식의 `edit` 도구 호출로 변환했습니다. |
| [ToolACE](https://huggingface.co/datasets/Team-ACE/ToolACE) | **1,000행**<br>단일 호출 333 / 병렬 호출 667 | **602행** | 함수·도구 선택과 입력 인자 작성, 여러 도구를 함께 호출하는 형식을 학습하기 위해 사용했습니다. 일반 도구 호출 데이터이며, 전부 CodePaze 프로젝트 실행 기록인 것은 아닙니다. |
| [xLAM irrelevance](https://huggingface.co/datasets/MadeAgents/xlam-irrelevance-7.5k) 기반 가공 자료 | **1,000행** | **615행** | 질문과 주어진 도구가 맞지 않을 때 호출을 하지 않도록 학습하기 위해 사용했습니다. 질문·도구 목록을 가져와 도구 비호출 응답으로 가공했으며, 정형화된 응답이 포함됩니다. |
| 공개 프로젝트 수정 참조 행동 | **17행**<br>C# 10 / C++ 7 | **8행**<br>C# 5 / C++ 3 | 일반 함수 호출 데이터와 실제 파일 수정 작업을 연결하기 위한 자료입니다. 검증된 참조 행동을 학습 형식으로 변환했습니다. |
| **합계** | **9,135행** | **5,600행** | **Tulu 데이터는 포함하지 않았습니다: 0행.** |

선정 기준은 **C++·C# 수정 작업과의 관련성, 원본 출처 추적, 코드 변경 내용, 도구 입력 형식, 학습 길이와 평가 자료 분리 여부**였습니다. 데이터가 공개되어 있다는 사실만으로 전체를 실행 검증된 고품질 자료로 판정하지는 않았습니다.

실제 반영량은 저장된 학습 데이터·설정·실행 코드의 해시를 확인하고, 학습 시 사용한 고정 섞기 순서에서 첫 5,600행을 복원해 집계했습니다. [선택된 데이터 집계](docs/selected-training-data-counts.csv)와 [복원 근거](docs/selected-training-data-audit.json)를 함께 공개합니다.

**참조 행동의 언어 표기는 출처 프로젝트 분류입니다.** 선택된 C++ 참조 3행은 OpenCC 사전 파일 작업에서 나온 것으로, 실제 C++ 소스의 컴파일 오류나 알고리즘 수정 사례로 세면 안 됩니다. 이 모델의 C++ 코드 수정 자료는 주로 CommitPackFT의 1,095행이며, C++ 프로젝트 전체의 에이전트 문제 해결 능력을 개선했다고 주장할 근거는 충분하지 않습니다.

### 데이터 검수에서 확인한 범위

- 수정 전·후 코드에서 교체할 구간을 추출하고, 교체 대상이 맞는지 확인했습니다.
- C++·C# 구문 검사, 도구 이름·인자 형식 검사, 중복 및 분할 검사를 적용했습니다.
- 길이를 초과하는 예제를 몰래 잘라 사용하지 않도록 했습니다.
- **CommitPackFT 7,118행 전체를 각각의 원본 프로젝트에서 빌드·테스트한 것은 아닙니다.** 코드 수정 참조 자료와 실제 프로젝트 검증 자료는 구분해서 관리했습니다.
- 학습과 평가 자료를 분리했습니다. BFCL 정답이나 자체 코드 평가 18건의 정답 패치를 추가 학습 자료로 복사하지 않았습니다.

전체 준비 데이터의 합계는 입력과 출력을 합쳐 **9,720,640토큰**, 그중 학습 손실을 적용한 출력은 **2,265,782토큰**입니다. 이 수치는 **9,135행 릴리스 전체 기준**이며, 아래 선택된 중간 체크포인트가 본 토큰 수와 동일하지 않습니다.

## 3. 이 공개 모델은 실제로 얼마나, 어떻게 학습했나

전체 학습은 2,284회 업데이트까지 실행했습니다. 공개 모델에는 마지막 결과를 그대로 사용하지 않고, 평가 결과를 보고 선택한 **1,400회 중간 체크포인트**를 사용했습니다.

**선택한 체크포인트가 학습한 양은 5,600행입니다.** 전체 준비 데이터 9,135행을 모두 학습한 모델로 해석하면 안 됩니다.

그 5,600행의 입력·출력 합계는 **5,946,661토큰**, 학습 대상 출력은 **1,398,741토큰**으로 복원 집계됐습니다. 이는 각 학습 예제의 문맥을 포함한 합계이며, 중복 문맥을 제거한 고유 문서 토큰 수가 아닙니다.

그 뒤 별도 C# 프로젝트의 검증된 수정 과정을 교정 자료로 사용했습니다.

후속 경계 조건 교정 모델은 BFCL 표본이 44/50으로 낮아져 이번 배포에 사용하지 않았습니다. 이 저장소는 **17/18·47/50을 기록한 직전 교정 모델**을 배포합니다.

| 구분 | 1차 LoRA SFT | 추가 교정 SFT |
|---|---|---|
| 학습 시작점 | 원본 Qwen3.8-27B | 선택된 1,400회 LoRA |
| 공개 모델에 반영된 양 | **5,600행 / 1,400회 업데이트** | **프로젝트 1건의 11행 / 3회 반복 / 9회 업데이트** |
| 학습률 | `0.00002` — `2e-5` | `0.00001` — `1e-5` |
| 배치 | 1개씩 처리, 4개씩 기울기 누적 | 최대 4개씩 기울기 누적 |
| 학습 길이 | 최대 8,192토큰, 학습 대상 출력 최대 2,048토큰 | 실제 최장 예제 12,242토큰, 문맥을 보존해 사용 |
| 학습 대상 | 원본 가중치를 고정하고 LoRA만 업데이트 | 기존 LoRA를 이어서 업데이트 |

공통 설정은 **LoRA rank 16, MLX scale 2, AdamW**입니다. 전체 64개 디코더 레이어 중 **뒤쪽 16개, 즉 49~64번째 레이어**의 Attention·GDN·FFN 선형 모듈에 적용했습니다. 새 Transformer 레이어를 삽입한 실험은 아닙니다.

학습 대상 출력에는 자연어 설명뿐 아니라 **도구 이름, 입력 인자, 파일 수정 내용, 작업 종료 설명**이 포함됩니다. 입력 코드와 이전 도구 결과는 문맥으로 제공하고, 해당 단계의 assistant 출력에 학습 손실을 적용했습니다. 교정 단계에서는 실제 설치된 서빙 입력 형식과 토크나이저 경계도 대조했습니다.

학습은 **Mac의 MLX 환경**에서 수행했습니다. LoRA 가중치 변경과 실제 optimizer 업데이트 기록으로 학습 실행을 확인했고, 성능 변화는 별도 평가로 판정했습니다.

### 실제 추가 교정 과제: C# Mapperly의 함수 선택 오류

자료는 공개 프로젝트 [riok/mapperly의 #2339](https://github.com/riok/mapperly/issues/2339)에 해당하는 별도 학습 사례입니다.

- **증상:** 개발자가 명시적으로 지정한 매핑 함수 대신 범용 `Identity<T>` 함수가 먼저 선택되는 문제가 있었습니다.
- **교정 내용:** `MappingCollection.cs`에서 선택 순서를 확인하고, `UseNamedMappingBuilder.cs`에서 이름으로 지정한 제네릭 매핑을 실제 타입으로 구체화하도록 수정했습니다.
- **참조 코드 검증:** 빌드 후 **1,703개 통과·2개 건너뜀**을 확인했습니다. 기존 1,701개 통과를 유지하며 실패하던 2개를 수정했습니다.
- **학습 형식:** 이 작업의 실제 도구 실행과 문맥 요약·종료 설명을 **11개 학습 단계**로 구성하고 3회 반복했습니다. **11개 프로젝트를 학습했다는 뜻이 아닙니다.**

이 테스트 통과 기록은 **교사가 제공한 참조 수정 코드의 검증**입니다. 모델이 스스로 1,703개 문제를 해결했다는 성능 지표가 아닙니다. 문맥 설정만 달리한 재실행에는 동일한 소스·동일한 수정 패치의 기존 검증 결과를 재사용했으며, 새 테스트 실행으로 중복 집계하지 않았습니다.

## 4. 파인튜닝과 RAG는 각각 무엇을 담당하나

**파인튜닝은 코드 분석·수정 작업을 학습시키는 데, RAG는 사내 문서·규칙을 답변에 반영하는 데 사용합니다.**

아래 왼쪽은 위에서 실제로 사용한 학습 과제입니다. **오른쪽의 사내 문서 이름과 규칙은 역할을 설명하기 위한 예시이며, 실제 회사 문서를 검색한 결과가 아닙니다.**

| 왼쪽 — 실제 코드 수정 학습 과제 | 오른쪽 — 사내 코딩 규칙을 찾아 적용하는 RAG 예시 |
|---|---|
| **요청**<br>“명시적으로 지정한 C# 매핑 함수보다 범용 함수가 먼저 선택됩니다. 원인을 찾아 수정하세요.” | **요청**<br>“이 코드를 수정할 때 우리 회사의 오류 처리·테스트 작성 규칙도 지켜 주세요.” |
| **사용하는 자료**<br>Mapperly의 오류 설명, 관련 소스, 수정 전·후 코드, 도구 호출과 검증 기록. | **찾아야 할 자료**<br>업로드된 사내 코딩 규칙과 PR 검토 지침의 관련 문단. 원문 위치·버전·적용 범위를 함께 확인합니다. |
| **처리 과정**<br>두 파일의 호출·선택 관계 확인 → 수정할 지점 선택 → 실제 파일 수정 → 빌드·테스트 결과 확인. | **처리 과정 예시**<br>문서에서 오류 처리·회귀 테스트 규칙 검색 → 관련 앞뒤 문단 확인 → 부족하면 추가 검색 → 현재 코드에 적용할 규칙과 근거 제시. |
| **결과**<br>요청에 맞는 코드 수정과 변경 영향 설명을 만드는 **작업 수행 방식**을 학습합니다. | **답변 예시**<br>“검색된 규칙이 오류 전달과 회귀 테스트 추가를 요구하므로, 패치에 이 두 항목을 반영하겠습니다.” 실제 답변에는 해당 문서와 위치를 인용합니다. |
| **확인 방법**<br>수정 코드의 빌드, 오류 재현 테스트, 기존 기능의 회귀 테스트. | **확인 방법 예시**<br>관련 규칙을 빠짐없이 찾았는지, 인용한 원문에 그 내용이 있는지, 코드 적용이 규칙에 맞는지 확인합니다. |

사내 문서는 별도 저장소에 원본을 보관하고 검색 가능한 단위와 출처 정보를 관리합니다. 질문할 때 검색한 내용을 모델 입력에 추가하는 구성이므로, **문서가 바뀔 때마다 모델을 다시 학습시키는 과정과는 다릅니다.** 검색 근거가 부족하면 추가 확인이 필요하며, RAG가 오답을 자동으로 없애 주는 것은 아닙니다.

이 저장소가 배포하는 것은 학습된 모델 가중치입니다. **사내 문서, 벡터 데이터베이스, 검색·재순위화 시스템이나 RAG 품질 검증 결과를 함께 배포하는 저장소는 아닙니다.**

## 5. 무엇을 근거로 체크포인트를 선택했나

학습 손실만으로 최종 모델을 정하지 않고, 실제 응답 평가를 사용했습니다.

| 평가 | 측정한 내용 | 원본 기록 | 공개 모델 기록 |
|---|---|---:|---:|
| 자체 C++·C# 코드 작업 18건 | CodePaze가 실제 파일을 수정한 뒤 빌드·오류 수정 테스트·기존 테스트를 통과했는지 | **18/18 — 100%** | **17/18 — 94.4%** |
| BFCL v4 50문항 표본 | 모델 API가 선택한 함수·입력 인자가 정답과 일치하는지 | **43/50 — 86%** | **47/50 — 94%** |

**확인된 변화는 BFCL 표본에서 정답 4개 증가, +8%p입니다. 코드 수정 정답은 원본보다 1개 적습니다.** 따라서 현재 결과를 “코드와 도구 사용이 모두 원본보다 좋아졌다”고 설명하지 않습니다.

- 코드 18건은 **자체 제작한 C++·C# 혼합 프로젝트의 오류 변형**입니다. 공식 SWE-bench 점수가 아닙니다.
- 코드 정답 17건 중 **7건은 코드·테스트는 통과했지만 에이전트 실행 시간 제한을 넘겼습니다.** 정상 종료까지 포함하면 10/18건입니다. 코드 정확도와 완료 시간은 분리해 기록했습니다.
- BFCL은 `simple_python`, `multiple`, `parallel`, `parallel_multiple`, `irrelevance`의 **5개 유형에서 각 10문항**입니다. CodePaze로 저장소를 수정하는 시험과는 다른, 직접 모델 호출 평가입니다.
- BFCL 50문항은 체크포인트 선정에 반복 사용했습니다. **독립적인 최종 확인 시험이나 전체 리더보드 점수로 간주하지 않습니다.**
- 같은 문제 세트와 동결된 하네스의 기록을 비교했지만, 원본과 공개 모델의 실행 시점·엔진 자원 프로필까지 일치시킨 독립 실험은 아닙니다. 이 결과로 속도 우위를 주장하지 않습니다.

## 6. 강화학습·MTP·현재 서빙 설정

**강화학습은 이 체크포인트에 적용되지 않았습니다.** 보상 계산과 GRPO 실험 코드는 별도 준비했지만, 실제 작업 보상에 따른 업데이트를 완료한 모델로 배포한 것은 아닙니다. 현재 모델의 교정은 정답 참조 사례를 학습한 **SFT**입니다.

**MTP는 추론 가속 설정입니다.** 학습 데이터나 강화학습 단계가 아닙니다. 병합 과정에서 원본의 내장 MTP 텐서 15개를 보존했고, GS의 oMLX 서빙에서 MTP를 활성화했습니다.

| 구분 | 설정 |
|---|---|
| GS API | `https://surving.geysersoft.com/v1` |
| 모델 이름 | `gs-qwen27b-agent-sft1400-corrected-mtp` |
| 현재 총문맥 제한 | **131,072토큰** |
| 현재 최대 출력 제한 | **65,536토큰** |
| 기본 샘플링 | `temperature=0`, `top_p=1`, `top_k=0` |
| MTP | ON |
| 배포 가중치 | LoRA 병합 완료 BF16 — 별도 LoRA 병합 불필요 |

평가 당시에는 요청 문맥 32K, 코드 작업 출력 최대 8,192토큰·medium thinking, BFCL 출력 최대 2,048토큰·thinking off를 사용했습니다. **현재 서비스의 더 큰 제한값과 평가 당시 설정은 구분해야 합니다.** 학습 예제 길이, 평가 요청 제한, 서비스 최대 문맥은 각각 다른 설정입니다.

이 가중치는 Mac oMLX에서 사용·평가했습니다. 해당 체크포인트의 CUDA/vLLM 실행을 별도로 검증한 결과는 이 카드에 포함하지 않았습니다.
