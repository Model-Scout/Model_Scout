# 짧은 개발 댓글 작성 방식 시험: 실패 기록

이 저장소는 **학습 자료나 모델이 아니라 공개 집계 문서**입니다. 새로운 가상 개발 상황 20그룹·60한영쌍·120문장을 작성하고, 언어별 첫 판정과 번역 쌍의 의미 보존을 따로 검토했습니다. 실제 업무 원문·개별 판정·문장·모델·프로파일은 게시하지 않았습니다.

문구 작성 전에 기준을 고정했습니다. 120개 모두 보존, 정규화 중복 0, 60쌍 모두 의미 검증 통과가 필요합니다. 각 언어에서 원래 ≤16자로 배정한 18개 중 15개 이상, 17–32자로 배정한 18개 중 15개 이상을 충족해야 합니다. 두 일반 그룹은 각각 같은 의미 검증 통과 쌍의 양쪽 문장 모두 ≥65 코드 포인트여야 합니다.

**결과: 의미 검토에서 56쌍 통과·4쌍 보류이므로 방식 시험은 실패입니다.** 주장 의미 보류 1건, 자연스러움 보류 3건입니다. 짧은 길이 충족은 한국어 ≤16 18/18·17–32 17/18, 영어 15/18·18/18입니다. 부적합한 문장을 제외하거나 길이를 재배정하거나 라벨을 바꾸지 않았습니다. 최종 결합 집계와 모든 실패·보류 분모는 `aggregate.json`에 기록합니다.

별도 한국어·영어 AI 검토자가 각각 자기 언어의 60문장과 공개 기준만 보고 첫 판정을 봉인했습니다. 다음 AI 검토자는 첫 판정을 보지 않고 번역 쌍과 사전 개념을 검토했습니다. AI 역할 분리는 사람 정답이나 완전한 독립성을 증명하지 않습니다. 언어별 라벨 일치와 문장 길이도 모델 정확도나 실사용 효용이 아닙니다. 활동·완료가 불명확한 사례가 적어 최종 자료의 지원량은 여전히 검증되지 않았습니다.

**이번 120개는 학습·모델 평가·골든셋·최종 2,400개에 합산하지 않습니다.** 최종 목표 400그룹·1,200한영가족·2,400문장, DEV 언어×속성×상태별 20가족·10그룹, 원래 스타일 및 확신도 0.9/마진 0.05 기준은 유지합니다. 새 Fit 0회, 누계 23회, 모델 질의·실제 앱 변경 0회입니다. 새 모델이나 Laya 학습·추론 결과를 주장하지 않습니다.

다음 후보 절차는 새 개념 모집 → 입력 전용 한영 편집 검토 → 제한된 보존 수정 → 전체 입력 봉인 → 새 언어별 첫 판정 → 별도 의미 검증입니다. 현재 문장을 고쳐 통과로 만들지 않고, 새 전체 자료 계획을 먼저 고정해야 합니다. 사람의 실제 표시 기준과 실사용 효용은 별도 증거가 필요합니다.

재생성 가능한 소유 Go 빌드 캐시 287,547,392바이트(274.23MiB)를 검증 후 제거했습니다. 원문·판정·모델·프로파일·증거는 보존했습니다. 이것은 추론 메모리나 처리 속도 측정이 아닙니다.
