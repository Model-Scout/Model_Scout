# Code + Multilingual Teacher Responses (Qwen3-235B-A22B-Instruct-2507)

This repo now contains **302,800 total samples** across the main blended
`data.jsonl` / `.parquet` file plus a second Nemotron-only file
(`nemotron_code_teacher_responses.jsonl` / `.parquet`). All responses were
generated by `Qwen3-235B-A22B-Instruct-2507` in **non-thinking mode**
(`enable_thinking=false`) to match downstream speculator training and eval.

Built in two batches: an initial 59,506-row batch (50K code + 9.5K
multilingual), followed by a second batch continuing from exactly where the
first left off (25K more code, 10K more multilingual, zero ID overlap with
the first batch) once early results showed the approach was working.

### Original code + multilingual batch

| `source` | Count | Prompts from | Responses from |
|---|---:|---|---|

| `multilingual` | 19,524 | [Aya dataset](https://huggingface.co/datasets/CohereForAI/aya_dataset) prompts, weighted toward the most commonly used languages (~630-790 samples/language for tier 1 — Spanish, French, Portuguese, Chinese, Japanese, Arabic, Italian — down to ~120-150/language for smaller tiers) | Qwen3-235B-A22B-Instruct-2507 (FP8), non-thinking |

Only the *prompts* were reused from Perfect Blend / Aya — every response here
is freshly generated by the teacher model, not the original dataset's own
human-written answer. 47 generations were dropped across both batches for
being empty/errored (24 in the second batch, 23 in the first).

Note: a few multilingual languages (German, Russian, and partially
Italian/Korean/Ukrainian) ran out of unused source rows in the second batch;
their shortfall was redistributed proportionally to other languages with
headroom, so the second batch's per-language counts aren't perfectly
proportional to the tier plan.

## Columns

- `id`: source dataset's row ID (string; code prompts use their original
  numeric ID as a string, multilingual prompts use `aya_<idx>`)
- `source`: `"code"` or `"multilingual"`
- `language`: language name for multilingual rows (empty string for code rows)
- `prompt`: the original question/instruction
- `response`: the teacher model's fresh response

## Generation details

- **Teacher model:** Qwen3-235B-A22B-Instruct-2507, FP8 quantized, served via
  vLLM (2 parallel TP=4 instances for throughput)
- **Sampling:** `temperature=0.8`, `max_tokens=2048` (code) / `8192`
  (multilingual, to accommodate longer non-English scripts)
- **Mode:** non-thinking (`enable_thinking=false`)
- We validated FP8 vs BF16 quality on a held-out 1,000-prompt sample before
  committing to this run (response length, code-block-parses-cleanly rate,
  refusal rate) and found no meaningful quality difference, with FP8 roughly
  1.7x faster on our hardware when run as two parallel TP=4 instances.

## Intended use

Built to blend into an existing broad instruction-tuning / distillation
training set (originally ~456k Magpie + UltraChat responses regenerated by
the same teacher) to boost code and multilingual coverage for training a
DFlash speculative-decoding draft model for Qwen3-8B. In its current form,
this repo contains code-heavy data from four visible source categories in the
main blended file (`code`, `multilingual`, `codealpaca_batch3`,
`nemotron_code_v1`) plus a second Nemotron-only file with 123,353 additional
rows.

## Nemotron code-split teacher responses

`nemotron_code_teacher_responses.jsonl` / `.parquet` — a second, independently
sourced set of (prompt, response) pairs for the same speculator-training
purpose, generated from NVIDIA's `Nemotron-Post-Training-Dataset-v2` "code"
split rather than Perfect Blend. Uses the same schema as `data.jsonl` above
(`id`, `source`, `language`, `prompt`, `response`) so the two files can be
concatenated directly; `source` is `"code"` and `language` is empty for all
rows here.

- **Prompts from:** Nemotron-Post-Training-Dataset-v2, "code" split
  (competitive-programming style Python), sampled without replacement across
  two generation rounds.
- **Responses from:** Qwen3-235B-A22B-Instruct-2507 (FP8), non-thinking mode,
  same teacher/serving setup as above (2x TP=4 vLLM instances,
  `temperature=0.8`, `max_tokens=8192`, `max_model_len=12288`).
- **Row count:** 123,353 successful generations out of 125,000 attempted
  (98.7%). The initial pass had a lower yield (114,516) due to 8,837
  generations dropped by client-side request timeouts that hit
  disproportionately under scheduler queue pressure on one serving instance
  -- not a data-quality issue with the prompts themselves. Those 8,837 were
  retried with a longer timeout (900s vs. the original 300s) and lower
  concurrency (32 vs. 64), succeeding on 100% of the retry. The remaining
  1,647 dropped rows (1.3%) are scattered low-rate failures across the other
  generation runs (empty/errored responses).
- **`id` format:** `nemotron_code_v2_<uuid>` / `nemotron_code_v3_<uuid>`,
  where `<uuid>` is the source dataset's persistent row UUID.
